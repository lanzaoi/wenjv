## D3 — 无依据拒答 / 弱上下文策略（G0）

**目标：** RAG 开着时，空检索不要一本正经瞎编。

### 做（后端优先）
- `use_rag=true` 且 hits 为空（或 score 差于阈值，若好做）：
  - 不调用或缩短生成；返回固定拒答 + 空 citations 或提示「库中未找到」
- 配置项示例（名称可调）：
  - `RAG_REFUSE_ON_EMPTY=true`
  - 可选 `RAG_MIN_HITS=1`
- 单测：空 hits → 事件含明确 refuse/error 文案，不出现胡编长文（可 mock search）

### 前端
- 展示拒答文案，不假装成功长答

### 验收
- [ ] pytest 覆盖空检索路径
- [ ] 手工：问一个库里没有的问题 → 拒答或明确无依据
- [ ] 用 D2 里 `should_refuse=true` 的 3 条回归

### 冻结
- 不做复杂置信度模型、不做 rerank

## D5 — Hybrid 检索 v0（G1 轻量启动）

**目标：** 专有名词/文件名类问题比纯向量稳一点；**默认关闭**，避免一上线行为大变。

### 做（选最简可行）
- 方案建议（YAGNI）：
  - SQLite FTS5 **或** 对 note/filename/chunk 文本做简单 LIKE/关键词打分（先个人库够用）
  - 与向量 top-k 做 **RRF 或加权合并**（实现一个即可）
- 配置：`HYBRID_SEARCH_ENABLED=false` 默认
- 单测：固定语料下，关键词命中文件名的 case

### 不做
- Elasticsearch
- 复杂中文分词套件（除非已有依赖很轻）
- rerank 模型

### 验收
- [ ] 默认关闭时行为 = 1.0
- [ ] 打开后：至少 1 个「纯向量弱、关键词强」的 D2 问题变好或持平
- [ ] README 写清开关与限制
