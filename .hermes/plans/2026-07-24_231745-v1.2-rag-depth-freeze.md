# 1.2 Freeze — RAG Depth（Rerank + MMR + 结构化召回 + 云端 OCR）

> **For Hermes / Gemini:** Implement task-by-task after **1.1 is tagged/merged**. Plan only until freeze confirmed.  
> **User intent (2026-07-24):** 先完善 RAG（本文件）→ **1.3** 再做测试加固 / 半自动 eval / 复现部署。

**Goal:** 在 1.1「向量 + FTS5 BM25 + RRF + 拒答」之上，补齐生产级检索后半程与扫描件入库，使专名/语义/元数据约束与扫描 PDF 都能进可靠上下文。

**Architecture（成熟主航道，禁止自创融合）:**

```text
Question
  → 权限硬过滤 (user_id) 始终在各通道
  → 多路召回
       ├─ Vector (Lance)
       ├─ Lexical FTS5 BM25 (已有，1.1)
       └─ Structured (SQL/metadata 通道，1.2 新增)
  → chunk_id 去重
  → RRF 融合 (已有；池子可放大)
  → [opt] Cross-Encoder Rerank  (默认 OFF)
  → [opt] MMR 多样性截断到 window_size  (默认 ON 轻量 / 可关)
  → citations + LLM (拒答逻辑不变)

Ingestion
  Source → Parser(text layer)
        → [opt] OCR stage if empty/thin scanned
        → chunk → embed → vector + FTS dual-write
```

**Tech Stack:** 现有 FastAPI / Lance / SQLite FTS5；Rerank = **云端 API**（优先 SiliconFlow `bge-reranker-v2-m3`，与双云 B0 一致）；OCR = **云端**（优先百度 AI Studio / PaddleOCR 官方 HTTP，与 Hermes MCP 同生态 token，**不**把本地 Paddle 绑进 RAG worker）；MMR = 纯向量数学，无新模型。

**Version cut:**

| 版本 | 主题 | 状态 |
|------|------|------|
| **1.1** | G0 信任 + Hybrid V+FTS+RRF | 进行中；**本计划前置** |
| **1.2** | Rerank + MMR + Structured + OCR stage | **本 freeze** |
| **1.3** | 黄金集扩题、半自动跑分、hybrid/rerank 门禁、失败体验、Compose/bat、API 隔离 | **后天/之后**，不进本包实现 |

## 0. 硬约束（继承 + 新增）

1. **成熟方案 only** — 不发明「多源拼假 rank」；LIKE 仍仅 `HYBRID_KEYWORD_BACKEND=like`，永不 FTS∪LIKE 假序列。  
2. **默认安全** — Rerank / OCR **默认 OFF 或 auto 保守**；未开时行为 = 1.1。  
3. **权限** — 结构化通道与 OCR 结果写入均带 `user_id`；召回前过滤，不靠排序降权。  
4. **云端密钥** — 只进 `%USERPROFILE%\.config\inquisitive\backend.env`；不进 git。  
5. **不做（1.2）:** Vue、workspace RBAC、热度引擎、假 HNSW、Agent、本地重型 OCR/本地 cross-encoder 必装、知识图谱。  
6. **1.1 未收口不得开 1.2 大改** — 至少：`pytest` 绿、hybrid/refuse 测在、freeze claim 可讲。  
7. **Implementer:** Gemini Task packs；路径白名单；人终验 P15 级抽检可放到 1.3，但 1.2 每柱要有 **pytest**。

## 1. 范围拆解（四柱）

### 柱 R — Re-ranker 精排

| 项 | 决策（推荐默认） |
|----|------------------|
| 模型 | SiliconFlow OpenAI 兼容 **rerank** API：`BAAI/bge-reranker-v2-m3`（免费档常见；与 embed 同厂） |
| 触发 | `RERANK_ENABLED=false` 默认；开启后对 RRF 后 **top `RERANK_CANDIDATES`（默认 20）** 精排，截断到 `window_size` |
| 失败 | 超时/4xx → **降级返回 RRF 结果**，打 warning，不炸 chat |
| 分数 | citation 可增加 `rerank_score`（可选）；禁止把 rerank 分伪装成「匹配度 87%」 |
| 依赖 | `httpx` 已有；**不**强制 `sentence-transformers` |

**配置项:**

```env
RERANK_ENABLED=false
RERANK_PROVIDER=siliconflow   # siliconflow | openai_compatible | off
RERANK_API_BASE=              # 空则回落 EMBEDDING_API_BASE
RERANK_API_KEY=               # 空则回落 EMBEDDING_API_KEY
RERANK_MODEL=BAAI/bge-reranker-v2-m3
RERANK_CANDIDATES=20
RERANK_TIMEOUT_SECONDS=8
```

### 柱 M — MMR 去重/多样性

| 项 | 决策 |
|----|------|
| 位置 | **Rerank 之后**（若 rerank 关则在 RRF 之后）截到 `window_size` |
| 算法 | 标准 MMR：`λ * sim(q,d) - (1-λ) * max sim(d, selected)` |
| 向量 | 优先用 **query 已嵌入向量** + 对候选 `page_content` **批量 embed**（候选 ≤20，可接受）；不做全库 MMR |
| 默认 | `MMR_ENABLED=true` 且仅当候选数 > `window_size` 时运行；`MMR_LAMBDA=0.7` |
| 与 link 去重 | 保留 `format_search_hits` 的 link URL 去重；MMR 在 chunk 级 |

```env
MMR_ENABLED=true
MMR_LAMBDA=0.7
```

### 柱 S — 结构化召回（Structured）

**定义（1.2 务实版，非图谱）:**  
第三条召回通道：用 **SQL 元数据 / 资源表** 命中「像在按业务条件找文档」的结果，再取其 chunk，与 V/FTS 一起进 RRF。

| 子能力 | 1.2 做 | 1.2 不做 |
|--------|--------|----------|
| 已有硬过滤 `source_type` / include / exclude | 保持 | — |
| 标题/文件名关键词 → 命中 Note/File/Link 行 → 拉相关 chunk | **做** | — |
| 标签 / 版本 / 产品线字段 | — | **不做**（无表；进 1.3+） |
| 知识图谱路径 | — | **不做** |

**实现要点:**

1. `backend/api/services/structured_recall.py`  
   - 输入：`prompt, user_id, limit`  
   - SQL：`notes`/`file_uploads`/`links` 上 `title`/`original_filename`/`filename`/`url` 的安全 LIKE 或简单分词 AND  
   - 输出：资源 id 列表 + source_type  
2. 将资源映射为 chunk：  
   - 优先 FTS/向量 metadata 过滤 `filename`/`title`/`link_id`；或  
   - 从 Lance `where` 拉该资源 chunk（若 metadata 含 file_id/note id——**先审计现有 metadata 字段**，缺则 1.2 入库补 `resource_id`）  
3. RRF 第三路权重 `HYBRID_RRF_WEIGHT_STRUCTURED=1.0`（等权起步）  
4. 开关：`STRUCTURED_RECALL_ENABLED=true`（可默认 true，因便宜且无外网）；无命中 = 空列表，不影响 V/FTS  

```env
STRUCTURED_RECALL_ENABLED=true
HYBRID_RRF_WEIGHT_STRUCTURED=1.0
STRUCTURED_RECALL_LIMIT=20
```

**注意:** 结构化是 **召回通道**，不是替代权限过滤。`source_type` 用户指定时仍硬过滤所有通道。

### 柱 O — 扫描件云端 OCR 入库 stage

| 项 | 决策 |
|----|------|
| 位置 | Parser **之后**、chunk/embed **之前** 的可选 stage |
| 触发 `OCR_MODE` | `off`（默认）/ `auto`（文本层空或总字符 < `OCR_MIN_CHARS`）/ `always` |
| 输入 | PDF 页（渲染或按页图）；可选后续 png/jpg 上传 |
| 客户端 | `backend/core/ocr_client.py`：HTTP 调 **AI Studio / PaddleOCR 云**（与 Hermes token 同名 env 可复用文档说明）；禁止 worker 内 `import paddle` 本地推理 |
| PDF 渲染 | 轻依赖：`pypdfium2`（纯 wheel，优于 poppler 绑系统）页→PNG bytes→OCR |
| 失败 | `auto`：OCR 失败且无文本 → job **FAILED** + 人话「扫描件 OCR 失败」；有部分页成功则尽力入库并 meta 标记 |
| 额度 | 页级计数日志；不实现复杂配额系统 |
| 图片直传 | 1.2 可选：扩展名 `png/jpg/jpeg/webp` **仅当 OCR 非 off** 时进白名单 |

```env
OCR_MODE=off
OCR_PROVIDER=aistudio          # aistudio | disabled
OCR_AISTUDIO_ACCESS_TOKEN=     # 或文档说明复用系统 env
OCR_MIN_CHARS=40
OCR_MAX_PAGES=30
OCR_TIMEOUT_SECONDS=60
```

**Parser 行为变更:**  
`pdf_parser` 在 `OCR_MODE=off` 时保持现状（空文本 raise）。  
`OCR_MODE=auto|always` 时：空/薄文本不直接 raise，交 OCR stage；仍全空才 FAILED。

## 2. 检索管道伪代码（实现真源）

```python
# search_documents (conceptual)
V = vector_top(k=pool)
K = fts_top(k=pool) if hybrid else []
S = structured_top(k=pool) if structured else []
merged = rrf([V, K, S], weights=...)  # dedupe by stable chunk id
if rerank_enabled:
    merged = rerank(query, merged[:candidates]) or merged  # fail-open
if mmr_enabled and len(merged) > window_size:
    merged = mmr(query_emb, merged, window_size, lambda_)
return merged[:window_size]
```

**池子:** `RECALL_POOL_MULTIPLIER=4` → `pool = max(window_size * 4, RERANK_CANDIDATES)`。
