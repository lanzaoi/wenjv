# Y2 FTS5 Hybrid Upgrade · Plan

> **Tier:** After 1.1 done. Upgrade Y1 (simple LIKE) → Y2 (SQLite FTS5).
> **Repo:** `feat/v1.1-g0-hybrid` (keep same branch).

## What

Replace `lance_db.py:fetch_documents_keyword()` LIKE-based keyword search
with a proper **SQLite FTS5 full-text index** on chunk metadata+text,
synced on every vector write/delete.

## Why

| Y1 (current) | Y2 (target) |
|---|---|
| `table.search(None)` + LIKE `%term%` | FTS5 MATCH with proper tokenization |
| No index — scan all rows | FTS5 virtual table with ranking (`bm25()`) |
| Chinese: whole prompt as substring | jieba segmentation + unicode tokenizer |
| No update/delete sync | FTS5 INSERT/DELETE at `add_documents` / `remove_documents` |

## Architecture

```text
SQLite: inquisitive.db
  ├── file_uploads / notes / links / ingestion_jobs  (existing)
  └── chunks_fts  (NEW — FTS5 virtual table)
       columns: id, title, filename, page_content, user_id, source_type
```

**Sync points (must cover all three backends: Lance/Chroma/Milvus):**

| Event | Lance function | FTS5 action |
|---|---|---|
| Document ingested | `add_documents()` | INSERT into chunks_fts |
| File deleted | `remove_documents()` | DELETE from chunks_fts WHERE filename |
| Link deleted | `remove_link_documents()` | DELETE from chunks_fts WHERE link_id |
| Note updated | durable job → re-ingest | DELETE old + INSERT new (same path) |
| Migration | one-time script | `backend/worker/fts5_backfill.py` |

## Chinese tokenizer

Use **jieba** (lightweight, pip-installable, MIT license) to pre-segment Chinese text before inserting.
FTS5 creation:

```sql
CREATE VIRTUAL TABLE chunks_fts USING fts5(
    title,
    filename,
    page_content,
    user_id UNINDEXED,
    source_type UNINDEXED,
    tokenize = 'unicode61'
);
```

On insert: `page_content` = jieba-segmented text (tokenizer further splits by unicode).
On search: segment query with jieba too, then FTS5 MATCH.

## Constraints

- Default still OFF: `HYBRID_SEARCH_ENABLED=false`
- jieba added to `requirements.txt`
- All three vector backends need sync in their own `add_documents`/`remove_documents`
- Migration script must handle empty FTS5 (first run) or re-sync (corner case)
- RRF merge in `search.py` — unchanged (just keyword source changes)
