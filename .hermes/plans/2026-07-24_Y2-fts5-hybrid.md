## 0. 一句话口径（简历 / README / 面试）

> Hybrid = **向量主检索 + 词法辅检索**。  
> 词法可来自 **FTS5（优先）和/或 LIKE（降级）**；用 **RRF** 融合，词法噪声大时可 **向量加权**。  
> **默认关闭**；用黄金集证明专名↑且语义不掉才推荐打开。

---

## 1. 三层决策（必须分开实现、分开测）

| 层 | 名称 | 做什么 | 本方案选择 |
|----|------|--------|------------|
| **L1 数据** | 存储与同步 | Lance 是否双写 FTS5 | **启用 FTS 后端时才双写 + backfill** |
| **L2 词法 K** | 关键词列表怎么来 | like / fts5 / fts5_then_like | **默认 `fts5_then_like`**（表空/失败则 LIKE） |
| **L3 融合** | V 与 K 怎么合成 | 对称 RRF / 加权 RRF | **默认加权：`w_v=1.0, w_k=0.4`**；可配回对称 |

**禁止混淆：**

- 「FTS5 主」≠ 整次检索以 FTS 为主角；只表示 **L2 装 K 时优先 FTS**。  
- 「向量主」= **L3 融合** 向量权更大，不是关掉词法。  
- **禁止** 默认三路独立 RRF（V + LIKE + FTS5 各算一路）。

## 2. 端到端查询流程（实现必须按此）

```text
search_documents(Q, user, ...):

  V = fetch_documents_vector(Q)   # Lance，租户过滤。始终执行。

  if not HYBRID_SEARCH_ENABLED:
      return V                    # = 1.0 纯向量

  # ----- L2: 词法列表 K（一条腿）-----
  backend = HYBRID_KEYWORD_BACKEND  # fts5_then_like | fts5 | like

  if backend == "like":
      K = keyword_like(Q)
  elif backend == "fts5":
      K = keyword_fts5(Q)         # 失败 → [] ，log
  else:  # fts5_then_like（默认）
      K1 = keyword_fts5(Q)        # 失败视为 []
      if len(K1) < HYBRID_KEYWORD_MIN_HITS:
          K2 = keyword_like(Q)
          K  = merge_unique(K1, K2)   # FTS 命中在前，LIKE 新命中在后
      else:
          K  = K1

  # ----- L3: 融合 -----
  if not K:
      return V                    # 词法全空则退回纯向量（稳健）

  final = weighted_rrf(
      lists=[V, K],
      weights=[HYBRID_RRF_WEIGHT_VECTOR, HYBRID_RRF_WEIGHT_KEYWORD],
      k=HYBRID_RRF_K,             # 默认 60
  )
  return final[:window_size]
```

### weighted_rrf

```text
score(d) = Σ_i  w_i / (k + rank_i(d))
# 某路没有 d 则该项为 0
# 按 score 降序
# 若需兼容「越小越好」的 distance 展示：distance = 1/score（文档写清量纲）
```

**对称 RRF：** 两路 weight 都设 `1.0` 即可（配置可切换，不必两套代码）。

## 3. 配置项（config + .env.example 必须有）

```text
# 总开关：默认关
HYBRID_SEARCH_ENABLED=false

# L2 词法后端
HYBRID_KEYWORD_BACKEND=fts5_then_like   # fts5_then_like | fts5 | like
HYBRID_KEYWORD_MIN_HITS=1               # FTS 命中数 < 此值则并 LIKE

# L3 融合（向量主默认）
HYBRID_RRF_K=60
HYBRID_RRF_WEIGHT_VECTOR=1.0
HYBRID_RRF_WEIGHT_KEYWORD=0.4           # 调 1.0 即接近对称 RRF

# 可选（有余力再做，非本包阻塞）
# HYBRID_TITLE_BOOST=...
```

| BACKEND | 含义 |
|---------|------|
| `like` | 仅 Y1 LIKE（对比基线、FTS 未就绪） |
| `fts5` | 仅 FTS5（严模式；表空则 K=[] → 退回 V） |
| `fts5_then_like` | **推荐默认**：FTS 优先，不够/失败 ∪ LIKE |

## 4. 入库 / 同步（仅 FTS 路径需要）

```text
add_documents:
  1) 写 Lance（向量 + page_content/title/filename）  # 始终
  2) 若 FTS 功能启用（代码常开工具层即可）:
       segment(page_content) → INSERT chunks_fts
       失败：log，不阻断向量写入

remove_documents / remove_link_documents:
  1) 删 Lance
  2) 删 FTS 对应行（失败 log）

backfill:
  python -m backend.worker.fts5_backfill [--dry-run] [--limit N]
  从 Lance 扫 chunk → FTS；同 chunk_id 不重复
```

**LIKE 不双写**——永远读 Lance 文本列。

### FTS5 表（参考）

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS chunks_fts USING fts5(
    chunk_id UNINDEXED,
    title,
    filename,
    page_content,
    user_id UNINDEXED,
    source_type UNINDEXED,
    link_id UNINDEXED,
    tokenize='unicode61'
);
```

- 写入/查询均 **jieba** 后再交 FTS（写入=查询同一 `segment()`）。  
- 避免列名 `doc_id`（FTS5 保留语义坑）。
