# 3分钟作品集演示台本与标准操作指引 (3-Minute Portfolio Demo Script & Guide)

本文档为 Inquisitive 个人知识库项目的 3 分钟录屏/现场口播演示台本，内含确保零失误可重复演示的**种子数据准备步骤 (Seed Steps)** 与**勿讲清单 (Do Not Mention List)**。

---

## 1. 种子准备与标准操作步骤 (Seed Steps)

为了在 3 分钟演示中稳定展示各类检索与问答特性，请在录屏或演示前按以下规范准备种子数据：

### 准备环境
确保在终端执行了 `pytest tests/ -q --disable-warnings` 绿灯通过（禁用警告可确保展示界面极其干净整洁），并且通过 `.env` 设置了基础配置（或保持系统默认的 LanceDB 嵌入式模式）。

### 1.1 预制种子笔记 (Note Ingestion)
在 Streamlit UI（页面 1：笔记管理）或使用 API 创建两条结构化 Markdown 笔记：
- **笔记 A (技术架构记录)**：
  - **标题**: `RAG 召回机制设计与演进.md`
  - **内容**: 
    ```markdown
    # RAG 召回机制设计与演进
    为了提高问答准确率，系统采用了三路混合召回架构。第一路是基于 LanceDB 的稠密向量召回（Vector），第二路是基于 SQLite FTS5 的词法倒排索引召回（Keyword），第三路是面向结构化资源的专属召回（Structured）。三路召回结果通过 RRF (Reciprocal Rank Fusion) 算法进行多路排序融合，并且可以通过配置开启 Cross-Encoder 深度重排（Rerank）与 MMR 多样性去重。
    ```
- **笔记 B (日常备忘)**：
  - **标题**: `2026年Q3系统硬件采购计划.md`
  - **内容**:
    ```markdown
    # Q3 采购计划
    计划于 8 月初为实验室服务器集群采购 4 张 NVIDIA RTX 4090 显卡，主要用于运行本地 BGE 向量模型与 DeepSeek 推理加速。
    ```

### 1.2 演示提问路径 (Repeatable Demo Query Path)
在 UI 的「AI 智能问答 (/chat)」模块中，按顺序演示以下两个标准问题：
1. **测试全库精准引用与召回**：
   - **输入问题**: `系统是如何提高 RAG 召回和问答准确率的？`
   - **预期表现**: SSE 流式快速吐字；页面下方**引用依据 (Citations)** 卡片准确高亮显示来源为 `RAG 召回机制设计与演进.md`。
2. **测试跨域精准定位**：
   - **输入问题**: `Q3 计划采购多少张显卡？用于什么用途？`
   - **预期表现**: 精准回答“4张 RTX 4090，用于本地 BGE 向量模型与 DeepSeek 推理”，引用指向 `2026年Q3系统硬件采购计划.md`。

## 2. 3分钟时间轴口播台本 (Timeline & Script)

### [0:00 - 0:30] 项目一句话定位 (Project Intro)
- **画面**：停留在项目主页或 Streamlit 聊天首界面。
- **口播**：
  > 「大家好，这是我独立开发的 Inquisitive 个人知识库系统。这是一款专注于隐私安全、零服务器依赖、可自托管的低维护成本 RAG 系统，旨在统一管理个人笔记、文档与外部链接，提供极速的语义检索与精确的追溯问答。」

### [0:30 - 1:30] 核心功能实操演示 (Live Demo: Search, Chat & Citations)
- **画面**：切换至 `/chat` 界面，输入演示提问路径中的第 1 个问题，展示 SSE 流式打字与下方引用的展开。
- **口播**：
  > 「现在我们进行现场问答演示。我输入关于系统架构的提问，可以看到后端通过 SSE 流式高速返回结果。请注意最下方的引用卡片，**引用始终指向库中来源**，点击即可溯源到原始切块，彻底杜绝了大模型幻觉。」
- **画面**：快速展示作业管理页面或上传页面，展示后台数据。
- **口播**：
  > 「在数据写入阶段，用户上传的任何文档和链接，都会触发**异步入库可恢复、retry** 的持久化任务队列。即便在大量文件解析或网络抖动时服务重启，系统也能断点续跑，确保数据切块与向量建立的绝对可靠。」

### [1:30 - 2:30] 深度架构亮点解析 (Architectural Highlights)
- **画面**：展示 GitHub 仓库的 `specs/architecture.md` 核心链路架构图，鼠标指向三路召回与存储模块。
- **口播**：
  > 「在底层的 RAG 引擎架构上，我们拒绝了简单的单向量检索，而是构建了**三路召回 V+FTS5+Structured → RRF → 可选 Rerank+MMR** 的多重融合流水线。向量捕捉语义，FTS5 倒排索引锁死精准专业词汇，最后通过倒数排名融合（RRF）与交叉重排产生最准的上下文。」
  > 「同时，我们在数据库层坚持严谨的权衡：**个人库规模用 LanceDB；扩展考虑 pgvector**。通过零外挂容器的 LanceDB 实现本地毫秒级 mmap 极速检索；同时代码层做了完整的适配器封装，面对团队多写高并发时可无缝下沉至 Postgres 与 pgvector。」

### [2:30 - 3:00] 总结收束 (Wrap-up)
- **画面**：回到终端展示 `pytest tests/ -q --disable-warnings` 100% 绿灯通过的干净测试终局。
- **口播**：
  > 「为确保系统工业级成熟度，我们建立了覆盖 70 个测试用例的自动化测试网格，包括严苛的 M-small 语料评估矩阵与物理级多租户安全边界隔离测试。Inquisitive 实现了在个人硬件上的低耗自托管与高度工程化，谢谢观看。」

## 3. 勿讲清单 (Do Not Mention List - Prohibition Protocol)

> [!CAUTION]
> 在演示口播和答辩过程中，为了严格对齐产品边界（Product Scope）、实事求是，**绝对严禁**提及以下不实或偏离定位的表述：

1. ❌ **严禁声称“系统目前基于 pgvector 或 Elasticsearch 运行”**。
   - *纠正*：必须诚实说明当前产线默认是 LanceDB + SQLite，pgvector 是面向团队多写的演进路线。
2. ❌ **严禁声称“实现了企业级微服务分布式集群架构”**。
   - *纠正*：定位为轻量级单机自托管（FastAPI + Streamlit + 嵌入式引擎），禁止过度吹嘘包装。
3. ❌ **严禁声称“拥有自研的 LLM 大语言模型或自研训练的 Embedding 权重”**。
   - *纠正*：系统基于 BGE / Ollama / SiliconFlow / OpenAI 等成熟模型进行 RAG 编排，核心价值在于工程管道与检索算法治理。
4. ❌ **严禁使用浮夸、缺乏实测证据的绝对化 AI 营销词汇**。
   - *纠正*：避免说“100%准确无敌”、“绝无任何 bug”，用“基于 MS MARCO 评估矩阵定量评测”与“通过 70 项回归测试”等客观实测依据说话。
