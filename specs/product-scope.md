# 产品范围与非目标 (Product Scope)

## 1. 产品定位

自托管 **wenjv（问据）知识库**：资料管理、异步向量化与带依据引用的检索问答。

## 2. 当前功能范围 (In scope)

- 笔记、文件与网页链接的增删查改管理
- 可靠的异步入库流程与显式异常状态落库
- 多格式文件解析（支持文本、PDF、Docx、PPTX 及可选图片处理）
- 行级租户逻辑隔离的语义与混合检索（可选 Rerank 二次重排，默认关闭）
- 后端统一编排的 RAG 流式问答（SSE 输出与引用来源标记）
- 多推理后端配置（支持云端兼容 API 与本地 Ollama 服务）
- Vue 3 + Vite 现代化单页面应用前端 (`web/`)
- 规范驱动的架构演进与评测基线（specs、plans 与 eval）

## 3. 明确非目标 (Out of scope)

| 非目标项 | 排除原因与设计考量 |
|----------|--------------------|
| 复杂自主 Agent 框架（动态工具调用闭环与多步规划） | 聚焦知识库 CRUD 与精准 RAG 问答，保持核心系统轻量透明 |
| 跨会话长期 Agent 记忆内核 | 系统通过知识库与会话窗口管理上下文，不额外构建黑盒记忆机制 |
| 复杂热度衰减与高频使用频次排序算法 | 自托管场景下数据规模可控，优先保障检索相关性与切块质量 |
| 宣称未经实装的分布式 HNSW 索引调优 | 遵循技术诚实原则，在未完成大规模验证前不做未落地宣称 |
| 老旧二进制 `.ppt` 格式完全解析 | 聚焦现代 `.pptx` 文本与元数据提取，老旧格式通过格式转换支持 |
| 企业级外部统一身份认证 (IdP) 与复杂组织架构审批流 | 聚焦单机与轻量团队自托管场景，暂不引入企业级身份联邦 |
| Kubernetes 编排与多地跨区域多活部署 | 采用轻量 Docker Compose 单节点部署满足资源与运维需求 |

## 4. 上下文与记忆管理决策

```text
知识库记忆   -> 向量数据库 + 关系型元数据库 (系统核心实现)
多轮会话上下文 -> history 参数滑动窗口 + 客户端状态管理 (系统核心实现)
会话记录持久化 -> 独立 conversation 实体表管理 (后续规划)
Agent 长期记忆 -> 属于系统非目标，不额外设计黑盒记忆系统
```

## 5. 权重机制决策

- 默认策略：不启用基于使用频次的复杂权重衰减。
- 允许的演进路径：
  - 显式资源级权重点赞或固定置顶
  - 引用计数的微弱平滑加分
  - 基于文档更新时间的轻量衰减
- 引入前提：必须具备标准评测基准，证明调整权重能够改善召回指标而非导致马太效应。

## 6. 演进节奏规划

架构升级依照分阶段演进原则推进：评测基线与拒答机制 -> 混合检索 -> 异常加固与服务层重构 -> 工作区扩展 -> 解析增强 -> 生产部署。

## 7. 技术宣传真实性自检清单

在对外介绍、编写技术文档或进行功能演示前，必须执行以下自检：

- [ ] 是否如实说明开源许可协议（AGPL-3.0）与技术演进背景？
- [ ] 是否如实说明文档解析的技术边界（如纯图片扫描件依赖 OCR，而非全自动完美版面还原）？
- [ ] 是否如实将多租户隔离表述为行级逻辑隔离，避免夸大为多机器物理隔离？
- [ ] 是否客观描述单机轻量自托管定位，而非宣称为高并发分布式微服务集群？

凡是不符合实际代码能力的夸大表述均违反本规范。
