# 安全规范 (Security)

## 1. 密钥与配置安全

- 核心密钥：`SECRET_KEY` 在生产及多用户环境中必须配置高强度随机串，严禁将真实密钥硬编码或提交至代码仓库。
- 外部模型凭据：第三方 API 密钥（如 SiliconFlow、DeepSeek 等）必须通过外部环境变量或本地配置文件注入。
- 占位密钥告警：系统启动时若检测到仍在使用默认占位密钥，必须在控制台打印显著安全告警。
- 配置文件路径：宿主机环境配置文件优先保存在 `~/.config/wenjv/backend.env`，底层保留对历史路径 `~/.config/inquisitive/backend.env` 的只读自动兼容。

## 2. 身份认证与多租户权限控制

- 认证实现：依托成熟的认证组件管理密码哈希与 JWT 签名验证，禁止明文存储用户口令。
- 凭证有效期：配置合理的 JWT 过期时效，支持生产环境自定义覆盖。
- 数据逻辑隔离：基于 JWT 解析出的 `user_id` 实施严格的行级访问控制，所有针对 Note、FileUpload、Link、Job 以及向量索引的查询和操作必须强制包含租户过滤条件。
- 工作区扩展约束：未来引入多工作区时，所有数据访问必须在租户过滤基础上叠加 workspace 成员关系校验。

## 3. 文件上传与存储防护

- 后端双重校验：在服务端强制执行文件扩展名白名单（`ALLOWED_UPLOAD_EXTENSIONS`）与单文件大小上限（`MAX_UPLOAD_BYTES`）校验。
- 前后端对齐：前端上传组件的格式限制作为交互提示，安全边界严格以服务端校验结果为准。
- 路径穿越防御：对所有上传文件名执行消毒过滤，严禁包含目录遍历字符 (`../` 或绝对路径)。
- 内容类型验证：不将客户端提交的 `Content-Type` 作为唯一的安全判定依据。

## 4. 外部网络请求防护 (网页链接抓取)

- 防范 SSRF 风险：针对用户提交的外部 URL，建立网络请求安全防护策略。
- 基础防护要求：设置显式的连接与读取超时上限、响应体体积截断以及标准 User-Agent。
- 进阶网络防护：在生产或多租户环境中，限制访问内网保留地址段（127.0.0.1、10.0.0.0/8、192.168.0.0/16 等）与敏感私有主机。

## 5. 跨域与网络暴露策略

- 开发阶段允许本地调试跨域；在面向内网或公网部署时，必须通过 `CORS_ORIGINS` 配置严格限定允许的来源域名。
- 公网暴露要求：必须配置 TLS/HTTPS 证书反向代理、自定义强随机密钥，并根据业务需求关闭公开注册接口 (`ALLOW_AUTO_USER_REGISTER=false`)。

## 6. 日志脱敏与隐私保护

- 日志输出中严禁打印完整的 JWT Token、用户密码明文或大规模文件正文内容。
- 外部错误响应中对系统内部真实物理路径执行脱敏，避免泄漏服务器宿主机目录结构。

## 7. 开源许可证合规

- 本项目代码遵循 **GNU Affero General Public License v3.0 (AGPL-3.0)** 许可协议。
- 通过网络对外提供修改版本或衍生服务时，需履行 AGPL 协议关于源代码提供的合规义务。

## 8. 安全改动自检清单

在提交任何安全相关代码前，必须对照执行以下检查：

- [ ] 新增 API 端点是否已正确配置身份鉴权依赖？
- [ ] 所有数据库与向量检索操作是否已注入租户过滤条件？
- [ ] 文件上传与解析链路是否已完成路径消毒与体积校验？
- [ ] 代码库中是否存在硬编码的默认密钥或测试后门？
- [ ] 向量数据删除操作是否严格限制在所属租户范围内，避免出现遗留或越权可见？
